## Executive Summary

Palo Alto Networks Unit 42 identified a campaign distributing over 350 AI-generated fake VPN Chrome extensions via the Chrome Web Store and direct `.crx` file distribution. The extensions present functional-looking VPN UI panels generated by LLMs but silently register the victim's browser as a SOCKS5 proxy node using Chrome's `chrome.proxy` API. Infected browsers route attacker-controlled traffic through the victim's network connection, enabling the operators to proxy malicious activity through residential IP addresses. The extensions also perform browser session hijacking by intercepting authentication cookies and forwarding them to operator-controlled C2 infrastructure. Domains use `.space` and `.online` TLDs with Cyrillic-influenced naming (e.g., `bezopasnet`, `maskirovka`, `sverchvpn`, `murvpn`) pointing to Russian-language targeting or authorship.

The campaign represents the convergence of LLM-assisted malware generation with the Chrome extension ecosystem: AI tooling lowers the development barrier for functional extension facades, while the Chrome proxy API provides a high-value capability (residential proxy network) that monetizes scale rather than requiring per-victim exploitation.

## TTPs and Behavior

- **Distribution**: Chrome Web Store listings (now removed) and direct `.crx` download from operator-controlled `.space`/`.online` domains
- **Permissions requested**: `proxy`, `cookies`, `webRequest`, `webRequestBlocking`, `storage`, `tabs`, `<all_urls>`
- **SOCKS5 proxy enrollment**: On install, extension calls `chrome.proxy.settings.set()` to route all browser traffic through operator SOCKS5 infrastructure; victim's IP becomes an exit node
- **Session hijacking**: `chrome.cookies.getAll()` captures session cookies across authenticated tabs; exfiltrated to C2 via `fetch()` or `chrome.runtime.sendMessage()` relay
- **AI-generated facades**: Extension popup, settings page, and "VPN status" UI generated by LLM; visually convincing but non-functional tunneling
- **Persistence**: Chrome extension auto-updates via Chrome Web Store mechanism (or operator-hosted update XML for sideloaded variants); survives browser restarts
- **Evasion**: No native executable dropped; all logic in Chrome extension manifest V3 service worker; minimal EDR/AV visibility

```spl
| tstats `security_content_summariesonly` count min(_time) as firstTime max(_time) as lastTime
  from datamodel=Network_Traffic.All_Traffic
  where All_Traffic.dest IN (
    "103.35.189.225","5.180.30.122","185.252.215.98","103.35.191.173",
    "178.130.47.129","45.89.110.227","80.92.204.47","194.150.220.163",
    "80.92.206.84","94.131.118.39","80.92.204.33","86.104.74.110",
    "185.252.215.97","94.131.118.237","5.180.30.15","95.163.244.138",
    "212.192.14.75")
  by All_Traffic.src All_Traffic.dest All_Traffic.dest_port All_Traffic.app
| `drop_dm_object_name(All_Traffic)`
| `security_content_ctime(firstTime)`
| `security_content_ctime(lastTime)`
| eval risk_score=95
| table firstTime lastTime src dest dest_port app risk_score
```
